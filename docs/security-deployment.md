## Earlier security hardening and operational checks

- Use `production.env.example` only as a starting template for a new deployment. Keep existing server `.env` settings; do not replace a working configuration with the example. Real `production.env` files are now ignored by Git.
- Rotate the database password previously committed in `production.env`, then update the server secret and connection configuration together. Removing the file does not erase Git history. Coordinate any history cleanup separately; never reuse that password. No live credentials were changed by this patch.
- Keep `APP_DEBUG=false` and `WEB_INSTALLER_ENABLED=false` on deployed sites. For a supervised fresh web install, temporarily enable the installer through server environment configuration and restrict network access. The setup session expires after 15 minutes; completion is allowed only against a database without application/migration tables. Updates additionally require a signed-in administrator listed in `ADMINISTRATOR_USERNAMES`. Disable web installation again immediately afterwards. The installer no longer drops existing tables.
- Configure the system scheduler to run `php artisan schedule:run` every minute from the project directory. Both `live` and `production` register backups, recurring invoices, rewards, and reminders. Check `php artisan schedule:list` after deployment; this does not run jobs. Verify backup destinations and mail configuration before enabling cron. Demo-reset jobs are restricted to `demo`.
- Deploy both PHP changes and the guest-payment Blade template together: payment confirmation now requires the invoice token and an enabled gateway.
- Apache must honor `public/.htaccess` with rewrite and headers modules enabled. On Nginx/IIS apply equivalent rules: reject active content and executable extensions anywhere under `/uploads/`, disable script execution there, set `X-Content-Type-Options: nosniff`, and serve documents as attachments with a sandbox CSP. The upload validator rejects active types and MIME/extension mismatches, including through the general document/image helper. Existing uploads are not deleted: review/quarantine unsafe legacy files separately.
- After deployment, verify a legitimate invoice payment and failure/retry using provider test mode, image/document uploads, administrator update access, and scheduler/backup operation. Local tests do not verify provider credentials, cron, web-server rules, or live mail.
